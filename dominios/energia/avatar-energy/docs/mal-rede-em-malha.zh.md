## teia-rede 今日所证（代码中测得）

| 组件 | 如何运作 |
|---|---|
| **发现** | 以确定性 infoHash 成群——网名之 20 字节哈希；入同群者互寻 |
| **信令** | 公共 WebSocket tracker（openwebtorrent、btorrent、webtorrent.dev）——WebRTC 要约交换 |
| **传输** | WebTorrent 于 WebRTC 数据通道之上；ICE 配 STUN（谷歌）——无 TURN，直连 P2P |
| **合流之技** | 每节点以同一 infoHash 播种自己的 JSON——群无内容服务器而聚合 |
| **应用协议** | 线上之 "teia-rede" 扩展；**流言**：连接即发态、定期重播、按 id 合并 |
| **分布式状态** | 映射（派系、领土、证据、案件）经流言同步并本地持久化 |
| **信任** | 连接即指纹（id + 地址 + 行为信号）——OSINT 血统 |

## 规格纠正之二弱

1. **中心化信令**：tracker 为单点——总崩溃时同坠。MAL 规格要求**无基础设施的本地发现**（LAN/mDNS、蓝牙 LE、直连二维码）为一等公民；
2. **消息未签名**：现行流言信任节点。规格要求逐节点密钥签名（TOS-019 之义）。

## MAL 规格

| ID | 需求 | 来源 |
|---|---|---|
| MAL-001 | **主题成群发现**：网名之确定性 infoHash——同主题之任意两节点互寻 | teia-rede |
| MAL-002 | **WebRTC 传输**（数据通道），ICE/STUN **可配置、可自托管**；同局域网免 STUN 直连 | teia-rede + 纠正 |
| MAL-003 | **多元信令**：可配置 WebSocket tracker 列表 **+ 本地发现**（mDNS、BLE、二维码）——基础设施崩而网存之网 | 纠正 |
| MAL-004 | **状态流言**：连接即发、定期重播、按 id 合并、确定性消解 | teia-rede |
| MAL-005 | **逐节点密钥签名之消息**——网上身份可验证 | 纠正（TOS-019） |
| MAL-006 | **连接即指纹与信誉**——信任挣得，而非假定 | teia-rede（OSINT） |
| MAL-007 | **双头参考实现**：现行用户脚本继续为真机活体实验室；TeiaOS 移植（Rust，规范 II）待软件卡开启时入流水线 | 规范 II + EST |
| MAL-008 | **总断电测试**：无互联网之局域网中两台 Teia Phone **结网**——灾难场景为验收标准，非愿景 | 架构师 |

## 网状之读

网状网络即字面之*网*——MAL-008 为其公民考试：**当一切坠落，两台 Teia Phone 仍相寻**。今日演练此局之游戏，成为明日保障此局之基础设施——而 poder-visivel 经此网分发（ECO-004）闭合成环：**大停电中的警戒**。
