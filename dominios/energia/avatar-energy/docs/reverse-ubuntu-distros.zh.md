# 逆向工程：Ubuntu Phone 与各大发行版 → TeiaOS

**Avatar-Energy · 2026年8月22日**

*TeiaOS 的第二个初始参数（第一个：GrapheneOS）：先知 Ubuntu Phone 死前所证明的，与在世大发行版共同证明的。*

---

## 第一部分 · Ubuntu Phone —— 先知（2013–2017，及其后）

**它是什么**：Canonical 的会聚系统——2013 年发布；Ubuntu Edge 众筹（1280 万美元，历史纪录）未达目标但证明了需求；2015 年实机（BQ、魅族）；**2017 年 4 月被 Canonical 放弃**；以 **Ubuntu Touch（UBports 社区）** 存续——今日运行于 Fairphone、Pixel 等。

**它证明的（TeiaOS 继承的）**：

| Ubuntu Touch 规格 | 对 TeiaOS 的价值 |
|---|---|
| **原生会聚**——入坞即桌面、真实窗口 | MOD-011 的最初证明 |
| **自适应声明式 UI**（QML/Unity 8，今 Lomiri） | 一套界面从口袋缩放到桌面 |
| **原子化 OTA 更新**（A/B 分区） | 系统绝不在更新中折断 |
| **应用隔离**（AppArmor） | 应用是被隔离的公民，而非持钥匙的房客 |
| **Libertine**——手机上的桌面应用容器 | 世界之间的桥 |
| **Halium**（UBports 方案） | 在现有安卓内核上启动 Linux 栈——**过渡之路**（TOS-017） |

**死因（诚实记录）**：应用从未到来（无 WhatsApp 则无用户；无用户则无应用），运营商/OEM 合作薄弱，烧掉约 2000 万美元以上。**墓园教训：杀死操作系统的是应用生态，不是技术。**

## 第二部分 · 在世发行版——各自证明什么

| 发行版 | 进入 TeiaOS 的课程 |
|---|---|
| **Debian** | 社会契约与社区治理——数十年有效的民主；中立基金会之形（SYS-006） |
| **Arch** | 成熟滚动发布：永远最新、以纪律保持稳定——基础 12 的"更新主流"，生产运行 20 年 |
| **Fedora** | 半年节奏与*先行*——Wayland、PipeWire、systemd 诞生于此 |
| **openSUSE** | **openQA**：自动化测试阵列在用户之前拦截回归——SYS-004 的闸门，真实存在 |
| **Ubuntu** | LTS 作为信任契约（2+5 年） |
| **NixOS** | 可复现构建、声明式原子更新与回滚 |
| **Alpine** | 极简底座（musl）——代码更少 = 攻击面更小**且运行能耗更低** |
| **Silverblue/不可变** | 系统底座不可变 + 分层应用——操作系统即镜像、应用即容器（TOS-012） |
| **postmarketOS** | 真手机上的主线优先——野生形态的 TeiaOS |

## 图形引擎（2026-08-22 决定）

```
APU（手机 / 坞 / 链）      ← APU-004：同构
  DRM/KMS      —— 主线内核
  Mesa         —— 引擎本体（面向所有目标的 Vulkan/OpenGL）
  Wayland      —— 原生显示协议
  wlroots      —— 合成器地基
  自适应 shell —— 架构师未来之选
```

## 游戏（TOS-023）：诚实

"100% 接受" = 一切可打开可运行——有原生则原生，Windows 血统则 API 翻译（Proton/DXVK/VKD3D），模块为 RISC-V 而游戏为 x86 则 ISA 翻译（Box64 级）。ISA 翻译有性能代价——这正是 APU 链存在的原因。不支持 Linux 的内核级反作弊按定义在需求之外。

## AI（TOS-024）：诚实

CUDA 是从前门被拒、从后门进来的大象：开放生态（llama.cpp/ONNX/ROCm/Vulkan）覆盖当前 AI 软件的主体；NVIDIA 独占的封闭栈是需求的边界。量化是 AI 的*节约*操作：Q8→Q4 把内存与能耗除以四、损失轻微——代理按电量选点。

## 应用市场：F-Droid 为基础规格（APL-001..007）

仅限自由软件；仓库索引签名；从源码可复现构建；多仓库（开放协议）；无账号、客户端无遥测；版本化通道可降级；**APL-006：F-Droid 本尊在 Waydroid 桥内供应安卓应用**——基础规格成为字面基础设施。

## 遗留集成层（INT-1..7）

运行他们的软件（Wine/Proton+Box64；Waydroid）；与他们的设备对话（Samba/mDNS/CUPS/MTP；KDE Connect 级协议）；**接收他们的用户**（INT-5 一次性迁移——采纳之桥：其余一切决定他们是否留下；这一条决定他们是否到来）。诚实边界：macOS 软件无可行的二进制层（Darling 仍属实验）。反囚禁规则：开放格式原生、遗留靠转换器——**绝不作为存储格式**。

## 终端（TOS-028）

完整 GNU 用户态（非模拟）；口袋模式屏幕辅助键盘；TUI 应用即公民；**同一会话**——shell、历史与环境从手机到坞完全一致；ssh 客户端与服务器；被隔离的应用保持隔离——**终端是所有者的权柄模式**。能耗读法：终端是现存最轻的界面——*节约*作用于 UI。

## 能耗读法

每个参数都有能耗维度：极简底座 = 常驻代码更少；不可变 = 无漂移、无救援重装；原子更新 = **没有半残系统**（重装是软件最大的浪费）；回滚 = 制度化的反浪费。而安卓桥（TOS-020）防止最大的浪费：**因缺应用而无人使用的完美系统**。
