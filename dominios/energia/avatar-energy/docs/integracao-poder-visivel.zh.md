# poder-visivel 集成：网上的警戒

**Avatar-Energy · 基础文档 19 · 2026年8月22日**

*生态系统第二项集成（首项：teia-rede，基础 18）。poder-visivel 之逆向规格与其集成于 Teia Phone 之 POD 规格。*

---

## poder-visivel 已是何物（仓库中测得）

| 组件 | 现存 |
|---|---|
| **平台** | Next.js 静态生成（构建 + 生成 API + 数据清单）——生而无后端 |
| **数据管线** | EJAtlas、世界银行、OWID、治理指标之抓取器——含 dry-run 模式与版本化快照 |
| **热点包** | 预打包专题包（"top 10"）——便于携带的危机数据 |
| **镜像套件** | Dockerfile、nginx、docker-compose、install.sh、manifest.sh——**任何人都已可镜像整平台** |
| **审计** | 自带脚本之 SBOM（sbom-audit）——经验证的供应链 |
| **移动/扩展** | mobile 与 extension 目录——口袋模式之种子已存 |

## POD 规格——poder-visivel 于 Teia Phone

| ID | 需求 | 来源 |
|---|---|---|
| POD-001 | **整座警戒入 microSD**：静态构建打包为受限本地应用（TOS-012）——平台离线运行于设备，无需任何网络 | 静态天性 |
| POD-002 | **数据为版本化签名包**：既有清单 + 签名（TOS-019）；经 ACS 通道更新 | 既有管线 |
| POD-003 | **热点包经 MAL 网分发**：专题包恰为 WebRTC 网之合适尺寸——警戒恰在危机中点对点扩散，服务器倒下、数据要紧之时 | MAL + 热点包 |
| POD-004 | **入坞之 Teia Phone 为社区镜像**：既有镜像套件 + 坞（MOD-010）= 入坞设备向局域网与网状网供给平台——无数据中心的社区警戒站 | 镜像 + 坞 |
| POD-005 | **管线于设备运行**：抓取器本地更新数据（一等终端 TOS-028，规范 II 之 Python）——数据于其居处更新 | 规范 II |
| POD-006 | **SBOM 纳入流水线**：既有审计成为闸门（EST-005）——无经验证之链不签名 | EST |
| POD-007 | 既有 mobile 目录为智能手机模式之种——依规格而入，非依情感（ECO-007） | ECO |

## 集成之读

POD-004 为重排地图之发现：**入坞后，Teia Phone 由客户端变为服务器**——容纳 APU 链（MOD-012 v4）的笔记本外壳化作社区警戒站：平台 + 数据 + 网状网，于停电中服务邻里。POD-003 则闭合晨间之环：poder-visivel 生而"不可摧毁、离线"——MAL 网即使不可摧毁成为字面。

*生态系统之对称：演练此网之游戏（基础 18）与监视权力之平台（基础 19）——两个从未相遇的项目，今被规格安排在一只口袋中相遇。*
