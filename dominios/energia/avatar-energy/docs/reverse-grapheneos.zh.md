*架构师方向：系统定名——**TeiaOS**（设备为 Teia Phone）——并以 [GrapheneOS](https://grapheneos.org/features) 为安全与隐私之初始参数。方法同基础 05/06/13：测量制品，提取规格。*

## 制品

**GrapheneOS**：量产中最强化的移动系统——非营利基金会、[严格纪律的签名更新](https://grapheneos.org/releases)，以及定义它的决定：**只在满足硬性要求的硬件上运行**（真实验证启动、Titan M 级安全元件、5 年以上更新）——至 2026 年仅限 Pixel，[摩托罗拉旗舰即将成为首个被接受的非谷歌设备](https://news.ycombinator.com/item?id=49360242)。结构性一课：**他们不为迁就更多设备而降低门槛——他们等设备升到门槛。**

## 测得规格

| GrapheneOS 规格 | 是什么 |
|---|---|
| **完整验证启动，用户密钥** | 安装后重新上锁引导加载器；每次启动对全链做密码学验证 |
| **无特权服务** | 谷歌服务以普通应用沙箱运行，唯用户所欲——无特殊待遇 |
| **细粒度权限** | 每应用的网络与传感器；*存储域*与*联系人域*——以假数据代替真实访问 |
| **hardened_malloc** | 强化内存分配器（堆利用大幅变难） |
| **Vanadium** | 强化浏览器，默认开启全部保护 |
| **完整性证明** | Auditor 应用以硬件验证系统未被篡改 |
| **签名、快速、可验证的更新** | 永远为全部受支持设备补齐补丁级别 |
| **攻击面缩减** | 移除遗留与调试代码；强化内核 |
| **按连接随机化** | 每网络新 MAC；一次性标识符 |
| **物理锁定** | 锁屏时 USB 数据断路；胁迫 PIN；自动上锁 |

## 转换——TeiaOS 初始参数

| ID | TeiaOS 需求 | 来源 |
|---|---|---|
| TOS-001 | 全链验证启动，用户密钥；可重新上锁引导加载器 | 验证启动 |
| TOS-002 | 无平台特权服务——一切运行者皆为普通公民 | 沙箱服务 |
| TOS-003 | 每应用细粒度权限：网络、传感器、假数据域 | 权限/域 |
| TOS-004 | 强化分配器为系统默认 | hardened_malloc |
| TOS-005 | 集成浏览器默认最高保护 | Vanadium |
| TOS-006 | 硬件完整性证明——系统自证未被侵犯 | Auditor |
| TOS-007 | 固定纪律的签名可验证更新，绝无例外 | 发布 |
| TOS-008 | 最小攻击面：移除遗留，强化内核 | 攻击面 |
| TOS-009 | 每连接一次性标识符 | 随机化 |
| TOS-010 | 物理锁定：锁屏断 USB；自动上锁；胁迫 | 物理强化 |

## 诚实之张力与硬件之课

GrapheneOS 基于 AOSP；TeiaOS 是规范 Linux 系统（基础 12）。**规格可迁移；实现各异**——每条 TOS 将有其 GNU/Linux 本体形态。

更大的一课：GrapheneOS 之所以安全，**因硬件合作**——安全元件、真验证启动、多年固件。TeiaOS 若不欲沦为愿景，MOD 须含：**外壳内置安全元件**与第一日即自有的启动链。硬件撑不住的软件规格只是营销——此依赖记录在案。

## 能耗读法

隐私与效率同行：**默认零遥测 = 更少射频唤醒**（基础 11 之论获安全参照印证）；沙箱运行时代价甚小；验证启动以数秒启动为代价，为稀疏更新所摊销。强化亦是*节约*——节约射频周期与注意力。
