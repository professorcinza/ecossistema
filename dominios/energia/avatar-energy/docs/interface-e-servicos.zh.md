# 人机界面与服务：IHU、MIG、ACS

**Avatar-Energy · 基础文档 23 · 2026年8月22日**

*设备的人之周界：如何被看见、听见、触及；如何抵达（迁移）；如何更新。*

---

## IHU——人机界面

| ID | 需求 | 注 |
|---|---|---|
| IHU-001 | **屏幕以结果定义，非以技术**：4.7–5.4"（MOD-008），**烈日下可读须持续 ≥ 600 尼特**，峰值 ≥ 1000 尼特，自适应刷新 120→60 Hz（帧之成本由 AVA 决定） | 测量，非手册 |
| IHU-002 | 多点触控带掌压抑制**并具手套模式**——与 MIL-STD 直接同调（MOD-019：活过冬天的设备须能戴手套操作） | MOD-019 |
| IHU-003 | 音频：街头可辨之扬声器与免提、双麦克风降噪、坚固振动马达 | 基本功做足 |
| IHU-004 | **相机为器具，非首饰**：libcamera 传感器（基础 10），目标=文档、二维码与**证据**之清晰（OSINT 血统：拍摄事实之相机，具诚实可签名之元数据——MAL-005） | 生态系统之职 |
| IHU-005 | 传感器：IMU、罗盘、GPS（受 ANT-005 断连开关）、光/距；气压计可选 P2 | 精瘦 |
| IHU-006 | **无障碍即 UI 之法**：单手原则升为规范（一切拇指可操）、一等读屏器配**本地** TTS（whisper.cpp，TOS-024）、AA 对比度、可缩放字体、无屏幕例外 | 无台阶之家 |
| IHU-007 | **3.5 mm 耳机口保留**——永恒之开放标准；听歌无需转接 | 自由同调 |

## MIG——迁移（INT-5 之细）

| ID | 需求 |
|---|---|
| MIG-001 | 自**安卓**：联系人（vCard）、文件（MTP）、开放格式之消息（标准 XML）、APL 仓库之应用等效映射 |
| MIG-002 | 自**iOS**：经 GDPR 导出（privacy.apple.com）+ vCard + 照片——苹果依法必给之路 |
| MIG-003 | 自 **Windows/macOS**：文件、浏览器书签与密码（须明确同意）、密钥 |
| MIG-004 | **无强制云**：经线（单口）或本地网状迁移——数据不为下行而上行 |
| MIG-005 | **迁移后报告**：何者已来、何者缺失、何者留后——无静默，无无录之失 |

## ACS——更新（交付）

| ID | 需求 |
|---|---|
| ACS-001 | 签名清单 + **二进制差分**——带宽最小化：网络能耗亦是能耗 |
| ACS-002 | 金丝雀 → 稳定，openQA 闸门（TOS-013）与自动回滚（TOS-011） |
| ACS-003 | **可选网状 P2P**：危机中邻里互更——热点包逻辑（POD-003）施于系统自身 |
| ACS-004 | **无设备因年迈被锁**，只要规范树活着（SYS-004）——基础 07 之诺，化为交付需求 |

## 人之周界之读

三领域之模式：**入门之门与室内同开**——以 UI 之法可达、无云可抵、无服务器可更、无转接可听。用户自遗留而来、居于家中、永不被锁于任何物——连耳机也不。
