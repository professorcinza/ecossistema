## 环路（结构核心）

```
测量 ──► 决策 ──► 执行 ──► 测量
(hwmon,     (版本化策略   (cpufreq,     (效果反哺
 powercap,   即规格)      devfreq,      策略)
 按链路)                  thermal)
```

## 诸要求

### 环路

| ID | 要求 | 源自 |
|---|---|---|
| AVA-001 | 代理即测量→决策→执行→反哺之环路——代理之外无物存在 | software/METODO |
| AVA-002 | **按链路测量**（基础 04）：按模块、按 APU 单元、按链之计数器；目标精度为智能电表级（±1–2%）；粒度足以逐链路审计损耗 | 基础 04 + TOS |
| AVA-003 | **决策即规格**：版本化策略（优先级、阈值、曲线）——无魔法逻辑；每一决策可追溯至授权之策略 | SDD 规范 |
| AVA-004 | **仅经主线接口执行**（cpufreq、devfreq、thermal、powercap、wake）——代理绝不给内核打补丁；永远上游优先 | SYS-005 |

### 对己之法

| ID | 要求 | 源自 |
|---|---|---|
| AVA-005 | **自身记账义务**：代理于系统仪表盘公布自身能耗——裁判亦为被告，每日，以瓦特计 | 家规（测量者自测） |
| AVA-006 | **架构性隐私**：能量数据本地化；匿名聚合仅限自愿加入；默认导出：**永不**——测量测量者的是规格，非善意 | 积压缺口（隐私） |
| AVA-007 | **每一决策皆有因可查**：审计日志含输入（测量）、规则（策略）、效果（执行）——能量不在黑暗中决策 | SDD 法 2 |

### 七操作作为服务

| ID | 要求 | 源自 |
|---|---|---|
| AVA-008 | **最大化**：按负载选择高效电压/频率点——取曲线，非峰值 | 概念 |
| AVA-009 | **重定向**：按可用性与能量成本在链间 APU 路由工作 | MOD-012 v4 |
| AVA-010 | **分配**：危机*之前*声明优先级类别（医院 > 游戏 > 空闲——口袋中的 CIV-ENE-005） | 基础 05 |
| AVA-011 | **节约**：按单元睡眠纪律（APU-006）与一切量化（系统之 Q4/Q8 点——TOS-024） | APU + TOS |
| AVA-012 | **储存**：电池健康管理、充电日历、两电池间之桥（MOD-017） | MOD-017 |
| AVA-013 | **分配电力**：模块与 dock 间交付协商（PD）与功率优先级 | MOD |
| AVA-014 | **减少浪费**：持续逐链路损耗审计、公开链报告（基础 04 之瓦特） | 基础 04 |

### 算法产品

### 智能（S3 之后）

| ID | 要求 | 源自 |
|---|---|---|
| AVA-018 | **本地优先智能，接口唯一**：底 = 规则与经典优化（始终在场、确定性、可审计）；顶 = 本地 AI（内核辩证管线，KER-004）于设备自身 APU 链上推理——若硬件不能支撑顶端，则等待硬件（D1 逻辑施于智能）。**无远程层**：无任何推理离开设备，亦不作为选项。决策 S3（2026-08-22）已选定引擎；环路之接口唯一，且不变 | S3 + KER-004 |

## 解读

十八项要求与一个原则：**代理是公仆**——以声明之精度测量，以公布之策略决策，以合法接口行动，一切记录有因，且在追究他人能耗之前先交代自身。基础 03 之管理层，终于有脸有责。
