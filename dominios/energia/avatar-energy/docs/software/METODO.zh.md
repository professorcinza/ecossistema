## 代理在软件中是什么

代理为七操作之执行者（项目概念）。作为软件：

```
        测量                   策略                   执行
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 按模块与链路的   │ → │ 七操作之决策     │ → │ DVFS、唤醒/睡眠、 │
│ 能量计数器       │   │ （优先级、阈值、 │   │ 充电、APU 链间    │
│ (hwmon, powercap,│   │ 成本）           │   │ 工作路由          │
│ RAPL-equivalent) │   │                  │   │                   │
└──────────────────┘   └──────────────────┘   └──────────────────┘
         ↑                                                        │
         └──────────────── 持续反馈 ──────────────────────────────┘
```

**结构原则**：测量 → 决策 → 执行 → 测量。项目之每个软件组件居于这四处之一。

## 七操作作为软件模块

| 操作 | 软件服务 | 主接口 |
|---|---|---|
| **最大化** | DVFS 提示与高效点选择 | cpufreq/devfreq |
| **重定向** | APU 链间工作路由（MOD-012 v4） | 自有分布式队列 |
| **分配** | 能量优先级调度器（医院 > 游戏 > 空闲） | 负载类别分类 |
| **节约** | 空闲纪律（APU-006）：不工作者沉睡 | wake-lock、runtime PM |
| **储存** | 充放电管理、电池健康、充电日历 | 智能电池、PD |
| **分配电力** | 供电协商（PD、优先级） | USB-PD、powercap |
| **减少浪费** | 链路审计：按链路测损（基础 04） | 累积遥测 |

另有已规划之两个算法产品：**APU 链编排器**（按负载唤醒/休眠单元）与**升级调度器**（基础 09 之优化问题）。

## 先于实现的三个决策

| # | 决策 | 选项 |
|---|---|---|
| S1 | **代理居于何处** | (a) 主线接口之上的用户空间守护进程（不触碰内核——SYS 一致之路径）；(b) 内核模块（需上游主线，周期缓慢） |
| S2 | **语言** | **已决策（2026-08-22）：RUST**——生态官方语言（枢纽之规范），登记例外：C 上游用 C，AI 工具用 Python |
| S3 | **本地智能** | **已决策（2026-08-22）：绝对本地优先。** 底：规则/经典优化——始终在场、确定性、可审计。顶：本地 AI（辩证管线，KER-004）于设备自身 APU 链上推理——若硬件尚不能支撑顶端，则等待硬件（D1 逻辑施于智能）。**无远程层**：产品中不存在远程 AI——亦不作为选项 |
