# 基础 34 — 远程之家：团队基础设施

**Avatar-Energy · 基础 34 · 2026年8月22日**

*架构师决策（2026-08-22，同日修订）：团队之开发管线运行于自托管、永远在线之 rakazo 实例——架构师专用之 **Mac mini 2012**，接以太网，每日异地镜像。本基础先于基础设施规定设计——先过闸门，后花分文。*

---

## 问题

团队需与持久机器人 24/7 对话。在架构师之**工作机**上运行 stack 经三重验证而失败：(1) 机器会睡眠，例行程序不触发；(2) 将其暴露于互联网，亦暴露架构师对 8 个仓库有 push 权限之 GitHub 凭据；(3) rakazo 处于 beta（生于 2026-08-13），托管产品"Rakazo Cloud"不存在——"随愿本地↔远程迁移"非该项目支持之操作。

答案为唯一之家，永远站立：机器人居于**专用 mini**（架构师家中，以太网，永开），经**仅出站之加密隧道、零开放端口**暴露给团队；架构师之工作机仍为客户。租用云（Hetzner/Fly）留作登记之 B 计划——mini 为 A 计划，租金为零，且本家论题亲身证明：**2012 年之机器于 2026 年服役，即 MOD-001 在家验证**。架构师声明并接受之风险：长时间停电将使之家下线至电力恢复——每日镜像保数据，不保可用性。

## INF 规格

| ID | 要求 | 源自 |
|---|---|---|
| INF-001 | **唯一之家**（v2）：专用 Mac mini 2012，永开，以太网——绝非架构师之工作机；工作机为客户（浏览器 + 本地 Hermes 自有终端） | 决策 |
| INF-002 | **诚实之尺寸**（v2）：mini 取代租用 VM（超过官方文档 2 GB 之地板）；机器人沙箱仍在家外——E2B/Daytona 供应商 | self-host.md |
| INF-003 | **沙箱在家外**：机器人计算机位于专用供应商（E2B 或 Daytona）——mini 只运行 API/worker/Postgres；执行隔离、可弃、绝不在家 | self-host.md |
| INF-003b | **模型凭据留于家中**：LLM 密钥以实例 ENCRYPTION_KEY 加密存于家之 Postgres；默认导出：**永不**——同 AVA-006 之法 | AVA-006 |
| INF-004 | **封闭注册**：`SIGNUP_ALLOWLIST` 限架构师之团队；无开放注册 | 决策 |
| INF-005 | **经隧道访问，永不开端口**（v2）：经仅出站加密隧道之 HTTPS——自有域名之 Cloudflare Tunnel，或可信团队之 tailnet；家中路由器**绝不**向 mini 端口转发 | 决策 |
| INF-006 | **每日异地镜像**（v2）：Postgres 转储 + DATA_DIR，**加密**，存异地（私有仓库或 B2），保留 7 天；每季度测试恢复——镜像保数据；长停电之可用性为接受之风险 | 决策 |
| INF-007 | **申报成本**（v2）：mini 电费（约 10–15 W 空闲 ≈ 每月 US$ 1.5–2）+ 镜像存储（约 US$ 0–2）+ 沙箱按用量——上限 ≤ US$ 20/月 保持有余；偏差 > 20% 触发规格复审，而非沉默 | 决策 |
| INF-008 | **受控升级**：固定 rakazo 版本；升级仅于 changelog 审阅后——beta 期预计有破坏性变更 | self-host.md |
| INF-009 | **Hermes 不变**：本基础不改变架构师之本地 Hermes CLI——月度 D1 继续于 Hermes，直至等效例行程序存在且于家中验证 | 决策 |
| INF-009b | **凭据离婚**：家不继承架构师之 gh 会话——需 GitHub 之机器人用细粒度令牌（限单一 fork 之 repo，或尽可能只读 deploy key），绝不用个人 gho_；mini 保持无个人凭据 | 决策 |
| INF-010 | **电力韧性**：停电后自动重启（`pmset autorestart 1`），禁用睡眠，建议 UPS（非强制）；家之能耗受申报——AVA-005 施于基础设施：**家以瓦特自述** | 决策 |
| INF-011 | **攻击面检验**：mini 上无隧道外之服务监听外部接口；对住宅 IP 之外部扫描找不到开放端口 | 决策 |

## 设计

```
   团队（浏览器/手机 ── 加密隧道 ──┐
   + 架构师工作机 = 客户）         │
                                  ▼
┌─────────────────────────────────────────┐
│ 家（专用 Mac mini 2012，以太网，       │
│ 永开，自动重启）                        │
│  API ─ worker ─ Postgres ─ DATA_DIR     │
│  模型凭据：加密于此                     │
└──────┬──────────────────────┬───────────┘
       │ 出站隧道              │ 每日加密镜像
       ▼ (E2B/Daytona)        ▼ (私有仓库 / B2)
┌──────────────────┐   ┌──────────────────┐
│ 计算机           │   │ 异地镜像         │
│ 每机器人         │   │ 保数据，         │
│ browser+shell，  │   │ 不保可用性       │
│ 短暂存续         │   │                  │
└──────────────────┘   └──────────────────┘
```

## 本基础非什么

- 非通往"Rakazo Cloud"之桥（其不存在）；乃开源代码之自托管
- 不移动家之规格工作：规格继续诞生于仓库，三语，依 SDD
- 不取代架构师之 Hermes（INF-009）
- 不承诺高可用：单一之家，单一电网——镜像为数据而设

## 角色

架构师提供 mini（SSH 访问）、团队 allowlist 与模型凭据。双手执行：整备 mini（pmset、Docker、stack）、隧道、镜像、监控。同一契约：草稿 → 审阅 → 验证。
