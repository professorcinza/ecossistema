# 开放架构上的 GPU 优化：性能 × 瓦特

**Avatar-Energy · 基础文档 14 · 2026年8月22日**

*架构师之问：如何在开放架构上以尖端手段最大化 GPU 开发——性能 × 能效？答案为七杠杆、一流程、一战略。*

---

## 七杠杆（影响排序）

### 1 · 制程节点——物理地板
每代节点免费赠 15–30% 能效：N4P（RX 9070）→ N3/N2 GAA 纳米片 → 2 nm 背面供电。**开放之证**：Tenstorrent 以 RISC-V 与芯粒 IP 供日本 LSTC 之 **2 nm** 边缘加速器——开放架构立于全球最先进节点。

### 2 · 数据搬运——沉默的主宰
搬一比特之皮焦多于算一比特。近年胜绩居于层级：大缓存（64 MB 无限缓存 = 少访 GDDR）、HBM 供带宽、近存计算。**屋顶线规则**：设计以每 FLOP 搬运字节最小化为先，非以 FLOP 最大化为先。

### 3 · 专用化——八成增益所在
张量单元（WMMA/FP8）、专用 RT、低精度算术——低精度 MatMul 为能效之最前沿。通用着色器已止步；按域加速器方升能效。

### 4 · 芯粒——硅中之 MOD
分解裸片：计算用贵节点、I/O 用廉节点、缓存三维堆叠。良率升、成本降、世代独立——**基础 09 之模块哲学入封装。**

### 5 · 细粒度 DVFS 与电源门控——纪律
逐单元调频调压、逐块断电：220 W 峰值与 <15 W 待机之别。峰值供有活之时；其余时候，机器近眠。

### 6 · 软件自首日共设计
RDNA4 之 Mesa 首日非侥幸——驱动与编译器入芯片设计环。开放之中迭代更快（社区在产品周期外修复、剖析、改进）。无共设计，半数效率失于软件。

### 7 · 正确度量——每焦耳之功，非峰值
优化 **tokens/s/W 与 FPS/W**，非手册 TFLOPS。峰值是营销；使用加权平均是物理——亦即代理之度量（基础 03：管理）。

## 开放端到端流程

| 阶段 | 开放工具 | 角色 |
|---|---|---|
| RTL 基座 | Vortex（佐治亚理工）——全栈 RISC-V GPGPU、可定制 | 开源起点 |
| 架构探索 | gem5 · Accelergy · Timeloop（MIT） | **流片前估算能耗** |
| 原型 | FPGA + 开放 PDK（sky130、IHP）+ OpenROAD | 廉价硅验证 |
| 生产 | 商用代工（无厂模式） | 架构应得之节点 |
| 软件 | LLVM · Mesa · Vulkan/SYCL | 自第一行共设计 |
| 保障 | 开放套件（如 Tenstorrent 之 1.3 万 RISC-V 测试） | 回归即阻塞 |

**流程金规**：自模拟器起测能耗——能耗是设计参数，非事后报告。

## 战略综合

**专用 RISC-V 芯粒 + 先进节点 + Mesa 共设计 + 每焦耳之功。** Tenstorrent 证商业模型存在；Vortex 证开放基座存在；两间乃生态系统之路：FPGA/开放 PDK 原型 → 低精度边缘芯粒 → 驱动入主线时入坞插槽。

闭合成环：以此法优化之 GPU 最顺服代理之七操作——有活则峰值、待机有纪律、芯粒可换、共设计开放。
